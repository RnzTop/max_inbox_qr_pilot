# MAX — PyMax только тест (без отправки)

**Экспериментальный прототип**, не для рабочего аккаунта. Исходники только в черновой ветке; образ собирается локально из проверенных исходников. Папка пригодна для локальной сборки Home Assistant Supervised на `aarch64`, но реальная совместимость PyMax с текущим MAX ещё не подтверждена.

- Вход через `PyMax WebClient` и QR; Chromium не нужен.
- Если PyMax не показывает имя личного диалога (`Chat.title=None`), в панели появляется одноразовая метка `MAX HA PAIR ...`. Её нужно отправить из второго тестового аккаунта в нужный чат. ID чата выбирается только после точного совпадения метки, а привязка сохраняется в `/data` как HMAC-отпечаток, привязанный к тестовому аккаунту и выбранному названию диалога. При перезапуске она автоматически восстанавливается; при смене аккаунта или названия потребуется новая привязка. Не публикуйте метку.
- Подключение только отдельного тестового номера. В параметрах обязательны `test_confirmed`, метка аккаунта и точное название тестового диалога.
- Наблюдение исключительно за **новыми входящими метками** `MAX HA TEST 1234` выбранного диалога. Ни сообщения, ни их ID, ни названия чатов в логах и базе не сохраняются.
- Для каждого нового сообщения сохраняется только HMAC-отпечаток пары `chat_id + message.id` (секрет в `/data/pymax_test/key.bin`). При перезапуске повторный ID не увеличивает счётчик уникальных.
- QR показывается только в локальной HA ingress-панели, а не в логах; не пересылайте снимки QR.
- **Никакого Bot API, polling, webhook, пересылки, ответов, отмечания прочитанным и просмотра истории.**
- Невозможно гарантировать, что веб-клиент не отправляет внутренние служебные пакеты MAX; «только чтение» означает отсутствие **наших** операций отправки сообщений.
- Пока тестируете браузерный QR-пилот, **не запускайте одновременно PyMax для того же номера** — возможны конфликты сессий.

Пошаговая установка и безопасная проверка описаны в [DOCS.md](DOCS.md). Остановите QR-пилот и установите эту папку как отдельное локальное дополнение (изображение собирается локально один раз). Для первого старта подтвердите тестовый режим и точное имя тестового диалога. Откройте ingress, отсканируйте QR, затем отправьте `MAX HA TEST 8351` из другого тестового аккаунта в указанный диалог. На панели должен увеличиться счётчик уникальных сообщений.

**Безопасность:** Сессия `/data/pymax_session.db` предоставляет полный доступ к тестовому аккаунту. Ограничьте доступ к папке и её резервным копиям. PyMax — неофициальный клиент MAX, его использование может быть ограничено условиями сервиса. Перед любым рабочим применением нужен отдельный тест на стабильность, восстановление соединения и пропущенных сообщений.

## Восстановление тестовых меток из истории (v0.0.4)

После первой авторизации и подтверждённой привязки сохраняется контрольная
точка времени в закрытой SQLite базе `/data/pymax_test/seen.sqlite3`.
**При первом запуске этой версии старую историю не импортируем**; контрольная
точка создаётся в момент первого подключения.

При повторном запуске PyMax только для привязанного личного диалога
делает read-only запросы истории `fetch_history` (до 10 страниц по 50
сообщений), обрабатывает только новые входящие `MAX HA TEST ####`,
а прежние идентификаторы подавляет по HMAC. В интерфейсе отображается
`Восстановлено из истории за запуск`.

Контрольная точка двигается только после полного ограниченного прохода.
Если сообщений больше 500, протокол недоступен или есть ошибка отметки
времени — пользователь увидит неполную проверку, а контрольная точка не
сдвинется. Более поздняя повторная попытка может завершить восстановление.
Тексты переписок и исходные chat/message ID не пишутся в базу или логи.
Если ранее привязанный чат отсутствует в первоначальном списке PyMax,
проверка запустится при первом новом входящем событии этого же чата.

### Безопасный тест

1. Убедиться, что панель версии 0.0.4 показывает подключение и счётчик.
2. Остановить **только** PyMax; отправить из второго тестового аккаунта
   `MAX HA TEST 8364` и `MAX HA TEST 8365` в привязанный диалог.
3. Запустить PyMax: ожидать `Восстановлено из истории за запуск: 2`
   и прирост общего счётчика на 2 без повторной QR-авторизации.
4. Перезапустить дополнение ещё раз: общий счётчик не должен увеличиться.
   Возможны записи о дублях от повторно прочитанных сообщений, но они не
   увеличивают количество уникальных.

Ограничение: тестировалось автоматическими заглушками PyMax; фактический
порядок и полноту истории на MAX нужно подтвердить на тестовом аккаунте.

## PyMax 0.0.5: устойчивость к отключениям и большим очередям

- Библиотека PyMax поддерживает повторное подключение WebSocket; при
  `on_disconnect` приватная привязка остаётся в SQLite, а после `on_start`
  проверяется история подтверждённого тестового диалога.
- Проверка истории повторяется каждые 60 секунд при активном подключении.
  Временная ошибка сети или запрос дольше 20 секунд не сбрасывает прогресс.
- Не более 10 страниц по 50 сообщений за одну проверку. Если новых записей
  больше 500, сохраняется промежуточная временная позиция; следующая
  проверка продолжает **тот же снимок**, даже после перезапуска контейнера.
  После завершения снимка последующая проверка возьмёт более новые записи.
- Только входящие `MAX HA TEST ####` из привязанного личного диалога,
  никаких отправок, чтения иных переписок, логирования текста, сырых ID
  или служебных токенов.
- В панели: количество обрывов MAX, ошибок истории и состояние дочитывания.
  Для полностью переполненных страниц с одинаковой миллисекундой времени
  чтение останавливается без сдвига позиции: PyMax не даёт ID-курсора,
  поэтому незаметный пропуск таких сообщений недопустим.

### Проверка без воздействия на основную сеть

Сначала убедитесь, что текущая работа PyMax завершена, и обновите только
это дополнение до 0.0.5 (автозапуск по-прежнему отключён). Остановите PyMax
на 1–2 минуты, отправьте несколько уникальных сообщений `MAX HA TEST ####`
из другого **тестового** аккаунта в подтверждённый тестовый чат, запустите
PyMax и проверьте рост общего счётчика. Повторный перезапуск не должен
увеличить количество уникальных идентификаторов. Для нагрузки более 1000
сообщений есть автоматический эмулятор на GitHub; не нужно генерировать
тысячи реальных сообщений MAX.

**Не отключайте интернет сервера HA ради теста**, не используйте хостовые
iptables/NetworkManager и не перезапускайте Supervisor. Настоящая потеря
соединения с MAX на оборудовании пользователя дополнительно нуждается в
наблюдении: локальные тесты имитируют `on_disconnect/on_start` и исключения API,
но не гарантируют поведение самого сервера MAX при всех сбоях.
