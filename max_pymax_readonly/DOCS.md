# MAX — тестовый PyMax без Chromium

**Эксперимент.** Только отдельный тестовый номер MAX. Не использовать для основной рабочей учётной записи. Этот WebClient использует неофициальный пользовательский протокол, совместимость не гарантирована.

## Установка в Home Assistant Supervised

Не добавляйте эту черновую ветку как новый репозиторий HA: существующий репозиторий уже содержит прежний пилот. Для теста используйте отдельное локальное дополнение.

1. Скачайте файл scripts/install_pymax_test_supervised.sh из GitHub и запустите через sudo bash с **полным commit SHA** проверенной версии, указанным при передаче на тест. Это загрузит max_pymax_readonly в локальный каталог Supervisor, не запуская контейнер.
2. В Home Assistant: **Настройки → Приложения (Дополнения) → Магазин**, затем меню **Проверить обновления**. В локальных дополнениях появится «MAX — PyMax только тест (без отправки)».
3. **Остановите старый QR-пилот**, если он использует тот же тестовый аккаунт. Не удаляйте пилот или его данные.
4. Установите новое дополнение. На первом запуске Supervisor соберёт Python-образ **без Chromium**. Не используйте Docker-команды старого пилота для нового дополнения — у них разные контейнеры и постоянные каталоги /data.
5. В параметрах укажите test_confirmed=true, произвольную метку тестового аккаунта и **точное видимое имя одного тестового личного диалога**. Метка — только надпись для вас, она не доказывает, какой аккаунт авторизован. Сканировать QR разрешается исключительно отдельным тестовым номером.
6. Запустите дополнение и откройте веб-панель, отсканируйте QR тестовым номером MAX.
7. Дождитесь статуса «Тестовый диалог найден». Отправьте из другого тестового номера входящую метку MAX HA TEST 8351, затем MAX HA TEST 8352. Убедитесь, что счётчик уникальных увеличился, а в тестовую группу **ничего не переслалось**.
8. Остановите и запустите дополнение ещё раз: сессия должна восстановиться без QR. Проверьте «уникальных за всё время» и отправьте новую метку MAX HA TEST 8353.

## Что показывает панель

- Статус QR / подключения / найденного тестового диалога / потери соединения.
- Уникальных новых тестовых меток **в этом запуске**.
- Повторов сообщений **в этом запуске** по ID; отсутствие повторов нормально.
- Количество уникальных ID тестовых меток **за все запуски**.

Приложение **не догружает историю и не гарантирует восстановление сообщений после потери связи**. Перед рабочим применением понадобится отдельное испытание пропущенных сообщений и ошибок декодирования.

## Безопасность и ограничения

- Только один выбранный личный тестовый диалог и новые входящие метки MAX HA TEST с 4–16 цифрами; нет истории, файлов, реальных заявок, Bot API, webhook или /updates.
- Тексты сообщений и ID чатов/сообщений не сохраняются в журнал или SQLite. /data/pymax_test/seen.sqlite3 содержит только HMAC-отпечатки; секретный ключ — /data/pymax_test/key.bin.
- /data/pymax_session.db — **секретная сессия полноценного аккаунта**. Никому не пересылайте эту базу, QR, дампы контейнера или резервные копии.
- Автоматическая повторная авторизация после отзыва сессии выключена (relogin=False); переподключение при сетевых обрывах включено.
- Интерактивный пароль 2FA пока **не поддерживается**. Если потребуется, тест завершится с безопасным сообщением. Не отправляйте пароль в чат или логи.
- PyMax — сторонняя библиотека, а использование внутреннего протокола может противоречить условиям MAX. Используйте **только отдельный тестовый аккаунт**.
- Доступ к панели ограничен локальным ingress HA, включены no-store и запрет внешнего контента.

## Возврат к предыдущей версии

Остановите PyMax-дополнение и запустите ранее установленный браузерный QR-пилот. Они независимы: разные контейнеры, сессии и базы. Рабочий бот и его polling не изменяются.
