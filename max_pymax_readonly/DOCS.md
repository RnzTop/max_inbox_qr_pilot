# MAX — тестовый PyMax без Chromium

**Эксперимент.** Только отдельный тестовый номер MAX. Не использовать для основной рабочей учётной записи. Этот WebClient использует неофициальный пользовательский протокол, совместимость не гарантирована.

## Установка в Home Assistant Supervised

Не добавляйте эту черновую ветку как новый репозиторий HA: существующий репозиторий уже содержит прежний пилот. Для теста используйте отдельное локальное дополнение.

1. Скачайте файл scripts/install_pymax_test_supervised.sh из GitHub и запустите через sudo bash с **полным commit SHA** проверенной версии, указанным при передаче на тест. Это загрузит max_pymax_readonly в локальный каталог Supervisor, не запуская контейнер.
2. В Home Assistant: **Настройки → Приложения (Дополнения) → Магазин**, затем меню **Проверить обновления**. В локальных дополнениях появится «MAX — PyMax только тест (без отправки)».
3. **Остановите старый QR-пилот**, если он использует тот же тестовый аккаунт. Не удаляйте пилот или его данные.
4. Установите новое дополнение. На первом запуске Supervisor соберёт Python-образ **без Chromium**. Не используйте Docker-команды старого пилота для нового дополнения — у них разные контейнеры и постоянные каталоги /data.
5. В параметрах укажите test_confirmed=true, произвольную метку тестового аккаунта и **точное видимое имя одного тестового личного диалога**. Метка — только надпись для вас, она не доказывает, какой аккаунт авторизован. Сканировать QR разрешается исключительно отдельным тестовым номером.
6. Запустите дополнение и откройте веб-панель, отсканируйте QR тестовым номером MAX.
   - Если видно «точных совпадений 0», это возможно для личных чатов: PyMax может возвращать пустое поле title. Панель покажет `MAX HA PAIR` и случайную 32-символьную шестнадцатеричную строку. **Скопируйте всю строку целиком и отправьте из другого тестового аккаунта именно в целевой личный чат MAX.** После сообщения «Тестовый диалог привязан» можно отправлять обычные метки. Одноразовая строка живёт только в памяти дополнения; после подтверждения привязка сохраняется в SQLite как HMAC-отпечаток и автоматически восстанавливается при следующем запуске. При изменении тестового аккаунта или настройки диалога понадобится повторная привязка.
7. Дождитесь статуса «Тестовый диалог найден». Отправьте из другого тестового номера входящую метку MAX HA TEST 8351, затем MAX HA TEST 8352. Убедитесь, что счётчик уникальных увеличился, а в тестовую группу **ничего не переслалось**.
8. Остановите и запустите дополнение ещё раз: сессия должна восстановиться без QR. Проверьте «уникальных за всё время» и отправьте новую метку MAX HA TEST 8353.

## Что показывает панель

- Статус QR / подключения / найденного тестового диалога / потери соединения.
- Уникальных новых тестовых меток **в этом запуске**.
- Повторов сообщений **в этом запуске** по ID; отсутствие повторов нормально.
- Количество уникальных ID тестовых меток **за все запуски**.

Приложение **не догружает историю и не гарантирует восстановление сообщений после потери связи**. Перед рабочим применением понадобится отдельное испытание пропущенных сообщений и ошибок декодирования.

## Безопасность и ограничения

- Только один выбранный личный тестовый диалог и новые входящие метки MAX HA TEST с 4–16 цифрами; нет истории, файлов, реальных заявок, Bot API, webhook или /updates.
- Тексты сообщений и ID чатов/сообщений не сохраняются в журнал или SQLite. /data/pymax_test/seen.sqlite3 содержит только HMAC-отпечатки; секретный ключ — /data/pymax_test/key.bin.
- /data/pymax_session.db — **секретная сессия полноценного аккаунта**. Никому не пересылайте эту базу, QR, дампы контейнера или резервные копии.
- Автоматическая повторная авторизация после отзыва сессии выключена (relogin=False); переподключение при сетевых обрывах включено.
- Интерактивный пароль 2FA пока **не поддерживается**. Если потребуется, тест завершится с безопасным сообщением. Не отправляйте пароль в чат или логи.
- PyMax — сторонняя библиотека, а использование внутреннего протокола может противоречить условиям MAX. Используйте **только отдельный тестовый аккаунт**.
- Доступ к панели ограничен локальным ingress HA, включены no-store и запрет внешнего контента.

## Возврат к предыдущей версии

Остановите PyMax-дополнение и запустите ранее установленный браузерный QR-пилот. Они независимы: разные контейнеры, сессии и базы. Рабочий бот и его polling не изменяются.

### PyMax 0.0.4: контроль пропущенных тестовых сообщений

После обновления и первого успешного подключения формируется начальная
контрольная точка. Старые сообщения, отправленные **до неё**, намеренно
не импортируются. Для проверки отправьте несколько **новых** сообщений
`MAX HA TEST 8364` и `MAX HA TEST 8365` из второго тестового аккаунта,
пока дополнение PyMax остановлено. После запуска проверьте счётчик
`Восстановлено из истории за запуск`. Должен увеличиться общий счётчик
уникальных меток. При повторном запуске те же ID не должны учитываться
как новые.

Обрабатываются только входящие сообщения проверенного личного диалога.
История читается с ограничением в 500 сообщений за проход, без пересылки
или изменения статуса прочтения. Если проход неполный, контрольная точка
не двигается. Если диалог не виден в недавних чатах, подождите входящей
метки: она позволит привязать событие к уже сохранённому HMAC и начать
догрузку. Из-за особенностей неофициального MAX API полнота восстановления
требует проверки на реальном тестовом аккаунте.

## PyMax 0.0.5: устойчивость к отключениям и большим очередям

- Библиотека PyMax поддерживает повторное подключение WebSocket; при
  `on_disconnect` приватная привязка остаётся в SQLite, а после `on_start`
  проверяется история подтверждённого тестового диалога.
- Проверка истории повторяется каждые 60 секунд при активном подключении.
  Временная ошибка сети или запрос дольше 20 секунд не сбрасывает прогресс.
- Не более 10 страниц по 50 сообщений за одну проверку. Если новых записей
  больше 500, сохраняется промежуточная временная позиция; следующая
  проверка продолжает **тот же снимок**, даже после перезапуска контейнера.
  После завершения снимка последующая проверка возьмёт более новые записи.
- Только входящие `MAX HA TEST ####` из привязанного личного диалога,
  никаких отправок, чтения иных переписок, логирования текста, сырых ID
  или служебных токенов.
- В панели: количество обрывов MAX, ошибок истории и состояние дочитывания.
  Для полностью переполненных страниц с одинаковой миллисекундой времени
  чтение останавливается без сдвига позиции: PyMax не даёт ID-курсора,
  поэтому незаметный пропуск таких сообщений недопустим.

### Проверка без воздействия на основную сеть

Сначала убедитесь, что текущая работа PyMax завершена, и обновите только
это дополнение до 0.0.5 (автозапуск по-прежнему отключён). Остановите PyMax
на 1–2 минуты, отправьте несколько уникальных сообщений `MAX HA TEST ####`
из другого **тестового** аккаунта в подтверждённый тестовый чат, запустите
PyMax и проверьте рост общего счётчика. Повторный перезапуск не должен
увеличить количество уникальных идентификаторов. Для нагрузки более 1000
сообщений есть автоматический эмулятор на GitHub; не нужно генерировать
тысячи реальных сообщений MAX.

**Не отключайте интернет сервера HA ради теста**, не используйте хостовые
iptables/NetworkManager и не перезапускайте Supervisor. Настоящая потеря
соединения с MAX на оборудовании пользователя дополнительно нуждается в
наблюдении: локальные тесты имитируют `on_disconnect/on_start` и исключения API,
но не гарантируют поведение самого сервера MAX при всех сбоях.
