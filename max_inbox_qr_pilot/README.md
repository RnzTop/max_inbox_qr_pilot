# MAX — QR-пилот тестового диалога

Отдельное локальное дополнение HA для arm64. Для проверки используйте только тестовый аккаунт, отдельного тестового бота и закрытую тестовую группу. Этот пилот читает только входящие текстовые метки формата MAX HA TEST 8432 из одного явно заданного диалога. Позиция строки используется только после проверки сохранения полного префикса видимых тестовых меток. При пропуске, перестановке или подгрузке, меняющей этот префикс, пересылка останавливается. Это не устойчивый ключ для произвольных рабочих чатов.

1. Распакуйте папку в каталог локальных приложений HA и установите «MAX — QR-пилот тестового диалога».
2. Укажите локально произвольную метку тестового аккаунта, точное имя отправителя в списке диалогов, имя отдельного тестового бота, его токен и числовой ID закрытой тестовой группы. Включите test_confirmed. Для первичной проверки в диалоге уже должна быть одна входящая метка.
3. Запустите пилот и откройте панель. Войдите тестовым телефоном по QR. Дождитесь статуса «Пилот слушает тестовый диалог», затем отправьте новую метку, например MAX HA TEST 8433. Проверьте карточку и кнопку в закрытой тестовой группе.
4. Перезапустите пилот, проверьте сохранение входа и отсутствие повторной карточки. Отправьте такую же метку снова и проверьте появление новой карточки.

Профиль Chromium и SQLite хранятся в /data. Доступ к резервным копиям с профилем ограничьте как доступ к аккаунту. Chromium запускается с sandbox. Если контейнер HA не предоставляет требуемую поддержку sandbox, пилот остановится. Образ и браузер внутри HA ещё не проверены. Пилот не поддерживает фото, телефон и произвольные тексты. Имена берутся из заданного тестового диалога. Публикация в закрытую группу осуществляется только тестовым ботом после проверки его имени, членства и отсутствия Webhook.

## Поиск тестового чата

Начиная с версии 0.1.1 дополнение ищет ровно одно видимое совпадение
`test_dialog` в браузере MAX, которым управляет само дополнение.
Больше не требуется конкретный HTML-класс `button.cell`.
В панели отображается количество точных видимых совпадений: 0 — в
браузере дополнения имя не найдено (проверьте, что этот аккаунт
авторизован через QR и что чат отображается в списке); больше 1 —
имя неоднозначно и переход в чат намеренно не выполняется.

Для проверки сначала отправьте в выбранный чат входящую метку
`MAX HA TEST 8432` и дождитесь сообщения «Пилот слушает тестовый
диалог». Это исходная метка; она не пересылается. Затем отправьте
`MAX HA TEST 8433` и проверьте новую карточку в закрытой тестовой
группе. Вход должен быть выполнен именно тестовым аккаунтом MAX.


## План подключения рабочего аккаунта и существующего бота

**Этот релиз всё ещё тестовый** и распознаёт только метки вида `MAX HA TEST 8432` в одном диалоге.
Не переключайте рабочий номер MAX и токен действующего бота на эту версию: она читает
`GET /updates` своего тестового бота, а действующий бот заявок уже обслуживает
свой Webhook или polling. Два обработчика событий с одним токеном могут потерять
события или сломать обработку заявок.

После подтверждения стабильных идентификаторов сообщений для множества диалогов
планируется отдельный рабочий режим:
- QR-клиент читает входящие сообщения рабочего номера, не управляя Webhook бота;
- действующий MAX-бот («Техцентр Приволжский») остаётся владельцем событий MAX
  и своей заявки на запись;
- уведомления и карточки отправляются в **тот же** `staff_chat_id`, что настроен
  у действующего бота (не создавайте новую группу);
- кнопки «Взять в работу» обрабатывает существующий бот, не второй polling-клиент.
  Такое расширение бота необходимо отдельно реализовать и протестировать.

### Уведомление при потере входа

В ветке эксперимента доступны два необязательных поля:
- `alert_bot_token`: токен **действующего** бота заявок; он используется
  **только для POST /messages**, без чтения событий и без изменения Webhook;
- `alert_chat_id`: скопируйте `staff_chat_id` из существующего дополнения
  «MAX — Техцентр Приволжский».

Не публикуйте токены в GitHub, журнале или переписке.

После подтверждённой авторизации, если Chromium показывает страницу входа,
в эту группу отправляется однократное предупреждение. После восстановления входа
отправляется отдельное сообщение. Начальный экран QR до первой успешной
авторизации не считается «слетевшим» входом. Состояние сохраняется в
`/data/auth_health.json` между перезапусками; не хранит клиентские сообщения.
При отсутствии связи с MAX повтор сообщения выполняется не чаще одного раза
в минуту.

Этот монитор пока **не проверяет** сбой доступа к чатам при сохранённой
авторизации, поэтому его нельзя считать полноценной системой контроля доставки.

### Быстрое обновление Python без сборки Chromium

После первого выпуска образа с новым `run.sh` в каталоге конфигурации
этого дополнения, видимом через Samba Share, можно положить `pilot.py`
или `auth_health.py`. В текущей установке из GitHub с ID `87928ab2`
это обычно:

`/app_configs/87928ab2_max_inbox_qr_pilot/`

Изменённый файл `pilot.py` имеет приоритет перед встроенным `/app/pilot.py`,
а модули Python в этой папке — перед встроенными одноимёнными модулями.
После копирования файлов достаточно **перезапустить дополнение**,
вместо пересборки большого образа. Для отката удалите переопределённый
файл из `app_configs` и снова перезапустите. Храните каталог в защищённом
доступе, так как Python-код в нём выполняется с доступом к настройкам
и авторизованной браузерной сессии MAX.
