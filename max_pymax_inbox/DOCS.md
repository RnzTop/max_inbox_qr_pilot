# Быстрый запуск MAX — Входящие обращения (PyMax) 1.0.0-rc2

## Потребуется

Рабочий MAX-аккаунт для QR-входа, **отдельный тестовый MAX-бот** с токеном
и ID закрытой рабочей группы. Добавьте этого бота в группу и **назначьте
администратором**. Проверьте, что у него нет действующего Webhook и что
другое приложение не получает события бота через GET /updates.

Клиентского действующего бота не подключаем и не меняем.

## Установка и обновление

- **Если ещё не устанавливали** max_pymax_inbox — используйте
  `scripts/install_pymax_production_supervised.sh` с полным SHA версии.
  Он создаёт только новую папку и не трогает существующие дополнения.
- **Если уже стоит rc1** — сначала остановите только max_pymax_inbox,
  затем используйте `scripts/update_pymax_production_supervised.sh` с
  тем же SHA. Обновляются исходники и конфигурация версии, а не
  /data: QR-сессия и очередь не удаляются.
- Обновите магазин локальных дополнений Home Assistant, установите
  дополнение или пересоберите только `local_max_pymax_inbox`.

В разделе **Конфигурация** ровно два поля:

- `bot_token` — токен **отдельного** тестового MAX-бота;
- `work_chat_id` — числовой ID закрытой рабочей группы.

Затем запустите дополнение, откройте веб-панель и отсканируйте QR
рабочим MAX-аккаунтом. Токен нужен исключительно для бота,
а QR — для отдельного приёмного аккаунта.

## Проверка кнопки

1. Отправьте личное текстовое обращение рабочему MAX-аккаунту с другого
   номера. Дождитесь новой карточки в закрытой группе.
2. Сотрудник №1 нажимает «Взять в работу». Кнопка должна исчезнуть, а
   текст дополниться «✅ Взял в работу: Имя».
3. Попробуйте нажать исходную кнопку повторно (если клиент сохранил
   старое сообщение) с другого аккаунта. **Исполнитель не должен
   поменяться**. В панели возрастёт «Взято в работу».
4. Перезапустите дополнение. Назначение останется в SQLite, и уже
   отправленные сообщения не должны дублироваться.
5. Если панель показывает «ожидают обновления карточки», проверьте права
   бота. Ошибки редактирования MAX не отменяют закреплённого сотрудника.

## Ограничения

- Long Polling у MAX предназначен для тестирования; для постоянной
  эксплуатации кнопок нужен HTTPS Webhook. Система не переключает
  Webhook самостоятельно и откажется стартовать при его наличии.
- При разрыве связи сообщения с неопределённым исходом отправки
  помечаются `uncertain` и не повторяются автоматически.
- Само приложение **не** отправляет данные в события/сущности HA;
  Home Assistant используется как контейнер-хост.
- Файлы, фото, голосовые сообщения: пока только уведомление о типе.
- QR, токен, конфигурацию и базы SQLite никому не отправляйте.
