# MAX — Входящие обращения (PyMax)

**Отдельное рабочее дополнение для Home Assistant Supervised, aarch64.**
Это кандидат на первый рабочий релиз `1.0.0-rc1`; исходный тестовый
`max_pymax_readonly` не меняется и его данные не используются.

## Как работает

1. Авторизует отдельный **рабочий MAX-аккаунт** через QR при помощи
   `maxapi-python==2.5.0` WebClient, без Chromium.
2. Принимает **новые входящие сообщения из всех личных диалогов**
   рабочего аккаунта MAX. Сообщения из групп/каналов и исходящие не
   отправляет.
3. Через **официальный MAX Bot API** публикует уведомления от имени бота
   в **один указанный закрытый рабочий групповой чат**. Перед первым
   сообщением проверяет `GET /me` и `GET /chats/{id}`.
4. Хранит приватную очередь в SQLite (`/data/inbox/inbox.sqlite3`).
   Дубли исходных ID отбрасываются по HMAC. При перезапуске очередь
   сохраняется, а история доступных личных чатов дочитывается.
   Проход ограничен 500 сообщениями одного диалога за вызов и
   продолжается с защищённой контрольной точки.
5. Использует Bot API **только для отправки**: не запрашивает
   `/updates`, не изменяет Webhook и не читает/не редактирует
   сообщения действующего рабочего бота.

**При первом входе не пересылает всю старую историю**: устанавливается
начальная граница по времени. После этого восполняются доступные
пропущенные сообщения. Полнота списка чатов зависит от ответов
неофициального API MAX; редкие и давние чаты могут не попасть в
ограниченный список при большом числе переписок. Указания
«гарантированная доставка» и «100% синхронизация» здесь неприменимы.

### Что пересылается

Текст сообщения, видимое имя отправителя (если MAX предоставляет его),
его MAX ID и сведения о типах вложений. **Фото, аудио, документы и иные
бинарные вложения пока не копируются**; в уведомлении явно указывается,
что вложение нужно открыть в исходном аккаунте MAX.

Кнопку «Взять в работу» этот релиз **не добавляет**: получение нажатий
требовало бы вмешательства в обработку событий рабочего бота, чего мы
здесь намеренно не делаем. Если в группе уже есть такой бот, его
существующая логика остаётся прежней.

## Приватность и безопасность

- **Все личные переписки** подключённого MAX-аккаунта, пришедшие после
  первого запуска, могут быть пересланы в указанный рабочий чат.
  Используйте только специально выделенный рабочий аккаунт и закрытую
  группу сотрудников. Не авторизуйте личный MAX-аккаунт.
- Сессия `/data/production_session.db` равнозначна доступу к учётной
  записи MAX. Токен бота находится в `/data/options.json` (параметры HA).
  Не публикуйте их, QR-код и резервные копии.
- В `/data/inbox/inbox.sqlite3` содержатся **тексты обращений**, пока
  они ожидают отправки, и сведения о доставке. Для уже доставленных
  текст стирается после 30 дней, а HMAC-отпечаток сохраняется для дедупликации.
- Отправка с неизвестным результатом (`uncertain`) **не повторяется**
  автоматически, чтобы не создать дубли при разрыве HTTP после
  принятия сообщения сервером. Панель показывает их количество —
  такие случаи требуют ручной сверки с рабочим чатом.
- Периодическая история обрабатывается только для личных диалогов.
  Группы и каналы игнорируются.
- Тестовая и новая версии имеют отдельные локальные slug/контейнер/сессию.
  Не запускайте две PyMax-сессии одновременно **на одном и том же
  QR-аккаунте**.
- Реальное использование неофициального протокола PyMax может быть
  ограничено правилами MAX. Устойчивость сервера MAX и доставка файлов
  ещё не проверены этим кандидатом.

Установка и запуск описаны в [DOCS.md](DOCS.md).
