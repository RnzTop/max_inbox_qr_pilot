# MAX — Входящие обращения (PyMax), 1.0.0-rc2

Отдельное локальное дополнение Home Assistant Supervised (aarch64), **не**
интеграция с сущностями или событиями HA. Поступающие личные сообщения
указанного QR-аккаунта MAX пересылаются в **закрытую рабочую группу**,
где выделенный **отдельный тестовый бот** показывает карточку с кнопкой
**«Взять в работу»**.

## Поток сообщений

1. Рабочий MAX-аккаунт авторизуется через QR PyMax WebClient, без Chromium.
2. Входящие личные сообщения (не групповые, не исходящие) попадают в
   SQLite-очередь /data/inbox/inbox.sqlite3. HMAC от исходного chat/message ID
   не допускает повторной отправки одной и той же заявки.
3. Выделенный тестовый бот через официальный MAX Bot API отправляет карточку
   в один закрытый чат с inline-кнопкой «Взять в работу».
4. При нажатии бот получает только событие message_callback, сверяет его
   с ID группы, исходным ID отправленной ботом карточки и локальным HMAC.
   Первый сотрудник атомарно закрепляется за обращением. Повторные нажатия
   не меняют исполнителя.
5. Бот подтверждает действие и редактирует **ту же карточку**:
   добавляет «✅ Взял в работу: Имя Фамилия», удаляет кнопку.
   При сбое редактирование восстанавливается после перезапуска.
6. Очередь обращений и контрольные точки истории сохраняются между
   перезапусками. Неоднозначная отправка карточки не повторяется вслепую,
   чтобы не создать дубликат.
7. Фото/голосовые/файлы пока только обозначаются по типу, но не копируются.
   Тексты сохраняются в закрытой SQLite; старые успешно доставленные
   тексты автоматически удаляются по истечении 30 дней.

## Отдельный бот — обязательное условие

Для кнопок дополнение использует GET /updates (Long Polling) **только у
отдельного тестового бота**. Бот должен:

- состоять в закрытой группе и быть её **администратором**;
- иметь рабочий токен, введённый в настройках этого дополнения;
- не иметь Webhook подписок; дополнение проверяет GET /subscriptions и
  отказывается работать при существующем Webhook;
- не использоваться другим клиентом GET /updates.

Токен и сессия клиентского бота не требуются и не изменяются. Дополнение
не вызывает POST/DELETE /subscriptions и не читает события чужого бота.

**Ограничение:** документация MAX разрешает Long Polling для разработки и
тестирования; для промышленного 24/7 бота рекомендуется Webhook. Эта
версия rc2 — кандидат для проверки выделенным тестовым ботом, **а не
гарантия промышленной надёжности кнопок**. Для круглосуточной эксплуатации
потребуется защищённый HTTPS Webhook и дополнительное испытание на MAX.

## Безопасность

- Сканируйте QR только рабочим MAX-аккаунтом, который предназначен для
  входящих обращений. Не используйте личный аккаунт.
- Не передавайте никому токен бота, QR и базы /data/production_session.db,
  /data/inbox/inbox.sqlite3. Резервные копии HA содержат секреты.
- В рабочий чат будут уходить новые обращения **из всех личных диалогов**
  авторизованного рабочего аккаунта, а не только одного контакта.
- Если исходный PyMax тест использует тот же QR-аккаунт, остановите его:
  два клиента с одной сессией могут мешать друг другу.
- В панели видно: сколько отправлено, взято в работу, сколько ожидает
  редактирования, ошибки сети и недоставленные карточки.
- Библиотека PyMax неофициальная, а история MAX может быть неполной. Полная
  синхронизация всех чатов и доставка файлов пока не подтверждены.

Пошаговая установка нового дополнения или обновление rc1 — в [DOCS.md](DOCS.md).
